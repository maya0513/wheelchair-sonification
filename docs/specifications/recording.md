# 記録形式

位置姿勢・速度はHMD、正式な課題時間と回答はPCへ保存する。研究ID・来訪ID・試行IDで対応付ける。実名は入力しない。通信形式は3、研究試行の保存形式は2で、旧接触角形式を速度として読み込まない。

保存先とコピー・復旧の操作は[保存先と記録の回収](../operations/records.md)を参照する。ここでは保存内容の意味を定義する。

## HMDの一試行

`ResearchSessions/<trial-id>/`の各ファイル。

| ファイル | 内容 |
|---|---|
| session.json | 形式、研究計画の識別子、研究ID・来訪・試行、群・時点・課題・反復、入力方式、FB設定、ビルド |
| calibration.json | 役割・機器ID、左右の回転軸、校正条件・有効性 |
| poses.csv | 取得時刻、取得できた入力時刻、機器、位置・姿勢、追跡・無効理由。手首も記録 |
| speeds.csv | 時刻、左右の符号付き生速度・平滑速度・提示値、有効性 |
| events.csv | 記録・FBの開始終了、取消、中断、欠測・校正無効化 |
| diagnostics.csv | 処理間隔、保存異常、取得できた機器状態 |
| eyes.csv | 毎描画フレームの左右視線・瞳孔・眼の開き、有効性、取得時刻・フレーム番号、頭部姿勢。左右1行ずつ |
| display.csv | 同じ時刻のバーの配置・表示状態・提示値と、Unityワールドに対する追跡原点の姿勢 |
| display.json | 幅・高さ・角度・不透明度、車体への相対配置、位置合わせの機器ID |
| eye-tracking.json | 追加記録形式1、API・SDK・座標系・単位、眼球校正の実施者確認、API成功、左右・両眼の有効率、取得間隔 |
| completed.json | ファイルを正常に閉じた印。正しい課題完了・正式採点の印ではない |

取得できないセンサー時刻・実提示時刻・電池等を推測で埋めない。定期書出しと終了時の書出しを行い、書込み失敗では提示・試行を停止する。元データを書き換えない。新しい試行の`study_protocol`は`single-visit-30min-pre-post`。旧ファイルに識別子を追加せず、保持評価の既存ログを直後評価へ読み替えない。

提示上限は`session.json`の`feedback.rangeRps`へ保存する。新しい既定値に合わせて過去の1.5 rpsの記録を書き換えず、再生はその記録に残る設定を使う。

視線は全群・全時点の試行記録開始から終了まで保存する。休憩中は試行記録を終了して保存を止める。旧ログの休憩時点にも取得停止の処理を維持する。眼球データはUnity追跡座標（左手系、メートル、前方+Z）へSDKの公式変換で変換し、方向は姿勢の前方ベクトルから求める。頭部とバーも同じ座標で保存するため、後から頭と眼の動きを分けて扱える。瞳孔径はmm、瞳孔位置はSDKの正規化座標、眼の開き等はSDK値である。

`software_time_s`はHMDの`realtimeSinceStartupAsDouble`による取得時刻。現在使うSDKの配列取得APIはセンサー時刻を公開しないため、`native_time`は空欄。描画ごとの取得回数をセンサーの標本化頻度とはみなさず、PCの正式計時と時刻値を直接結合しない。実提示時刻とも異なる。

取得不可・片眼欠測・API失敗を区別し、無効値の数値欄は空欄にする。直前値や頭部方向で補完しない。視線の欠測だけでは試行やFBを停止しない。SDKは準備中にも状態確認するが、試行外の視線はファイルへ書かない。視線の処理は探索用記録までで、注視対象の分類や群間検定は未実装。視線データだけで注意・認知負荷を断定しない。

## 単体チェック

`DeviceChecks/<check-id>/`の各ファイル。トラッカー登録・動作確認・FB検査は別々のチェックIDで保存する。参加者IDや来訪を作らずに保存でき、研究試行と混ぜない。`report.json`の`mode`と`scope`で対象を示し、対象外は`not_in_scope`とする。

| ファイル | 内容 |
|---|---|
| report.json | 段階、割当候補、項目別の確認済み・要確認・未実施、理由 |
| poses.csv | 未割当も含む全機器の元の位置姿勢・入力時刻・有効性。研究試行と同じ列 |
| speeds.csv | 動作確認中の符号付き左右速度、有効性、段階。見本の値を実測として記録しない |
| settings.json | 自動候補・静止・校正の設定 |
| calibration.json | 役割と回転軸、有効性 |
| operations.csv | 操作と段階の遷移。HMDとPCの操作を共通処理で記録 |
| build.json | 入力方式、アプリ・Unity・ソース識別、開始UTC |
| closed.json | ファイルを閉じた印。チェック完了か中断かを区別 |

保存失敗や強制終了では最後まで揃わないことがある。`closed.json`のない記録を正常完了と扱わない。機能チェックの結果は測定精度・実出力遅延の検証結果ではない。元データは記録再生の入力として読めるが、研究試行用の速度再解析とは区別する。

`confirmStopped`は実施者が安全停止を確認して準備画面へ戻った操作。静止の計測値や検査合格とは区別し、中断されたチェックを完了へ変更しない。

## 自由走行

自由走行では研究試行・チェック記録・視線記録・正式計時を作らず、ファイルへ保存しない。開始・終了で既存の研究来訪記録を書き換えず、自動回収も行わない。PCへ送る現在の左右速度と追跡状態は、その場の表示に使う。

## PCの記録

| ファイル | 内容 |
|---|---|
| 回収ZIPとSHA-256 | 試行またはチェック一件分。内部ファイルのSHA-256一覧を含み、外側のSHA-256もPCで照合 |
| archives.json | 回収済みZIPの識別子・ファイル名・サイズ・SHA-256の対応 |
| 来訪ごとのoperator.json | 研究ID・来訪ID、試行ID付きの正式計時、理解確認・質問紙、手動操作・逸脱 |

正式計時には単調時計での開始・終了・経過秒、合図のWeb Audio予定時刻とソフトウェア通知時刻、取消・未完了理由を残す。ブラウザー再起動をまたぐ時計を結合しない。PCとHMDの対応は試行IDと操作標識で行い、異なる時計を精密同期済みとは扱わない。[計測仕様](measurement.md)

理解確認の見本記録には提示を要求した左右速度と上限を残す。命令の送信は実際に見えた・聞こえたことの証拠にせず、装着者の回答を別に記録する。通信状態には現在の上限、位置合わせの可否・理由、手動停止確認の可否を追加し、通信形式は3を維持する。

保存を正常に閉じたこと、課題を正しく完了したこと、計時が成立したこと、PCへの回収が済んだことは別の状態として扱う。過去データを新形式へ書き換えず、対応しない形式を速度データとして読み込まない。
