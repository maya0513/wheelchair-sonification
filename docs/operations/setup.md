# 導入・装着・準備

実施者がアプリを入れて機器の動作を確認するまでの手順。案内付きチェックはゴーグル単体でも行える。本実験は[PC操作](console.md)と[実験手順](../experiment-protocol.md)に沿って行い、参加者にメニュー操作を求めない。

## 用意するもの

| 機器・配布物 | 用途 |
|---|---|
| VIVE Focus Vision、VIVE Wireless Dongle | Android単体で計測・提示・保存 |
| Ultimate Tracker | 左車輪・右車輪・車体の3台が走行用。左右手首の2台は元データの追加記録用 |
| ノートPC、対応する版のリポジトリ | オフライン接続、実験操作、正式計時、回収 |
| 対応する`WheelchairSonification.apk` | ゴーグルに入れるアプリ |

走行用3台でも機能チェックできる。研究計画の5台構成や本計測の受入れ条件を変更するものではない。実機で確認できた範囲は[確認状況](../status.md)に残す。

## 1. アプリとPCを用意する

1. [Releases](https://github.com/maya0513/wheelchair-sonification/releases)から`WheelchairSonification.apk`を入手する。
2. Focus VisionをWindows PCへUSB接続し、ゴーグルでファイル転送を許可する。APKを「内部共有ストレージ → Download」へコピーする。
3. ゴーグルのファイルブラウザーでAPKを開き、不明のアプリの許可を確認してインストールする。[HTC公式手順](https://www.vive.com/jp/support/focusvision/category_howto/installing-apk-on-headset.html)
4. 実施者用Ubuntu PCではリポジトリを同じReleaseの版へ更新し、初回は`just setup`で準備する。

APKとPC側のリポジトリは同じ版を使う。通信形式は3。同じアプリID・署名鍵で更新し、署名不一致ならアプリのバージョンと鍵を確認する。アンインストールすると元データを失うため、更新の代わりに行わない。自分でAPKを作る場合は[ビルド手順](../development/android-build.md)を参照する。

公開する添付物はAPKだけ。[画像付き説明](../app-overview.md)と[画面・音の確認](../development/xr-preview.md)はリポジトリで読む。プレビューは実機の光学系・計測性能を再現するものではない。

## 2. トラッカーを接続・固定する

HMDへドングルを取り付け、「設定 → 入力 → モーショントラッカー」でペアリングと環境スキャンを済ませる。アプリはHMDが取得した位置姿勢を使い、ペアリング自体は行わない。[HTCの設定手順](https://www.vive.com/jp/support/ultimate-tracker/category_howto/setting-up-vive-ultimate-tracker.html)

車輪用は回転する部分、車体用は剛性のあるフレームへ固定する。カメラを覆わず、手・衣服・車体・床との干渉、脱落、固定部のずれを確認する。背もたれの布だけを車体基準にしない。装着の強度・全走路の追跡は実機で確認する。

## 3. PCとゴーグルをつなぐ

1. PCのWi-Fi設定でホットスポットを作り、Focus Visionを接続する。会場のWi-Fiや外部回線は不要。
2. リポジトリで`just start`を実行し、`http://127.0.0.1:8765/`を開く。更新前から起動していた場合は終了して再起動し、ブラウザーも再読み込みする。
3. ゴーグルでアプリを起動する。PCがゴーグルを検出したら、表示された6桁番号を照合し「接続を承認」を押す。

Unity・VIVE Hub・外部回線の常時実行は不要。コンソールはネットワークを切り替えず、起動時のホットスポットだけで機器通信を受ける。ホットスポットを後から有効にした場合はコンソールを起動し直す。HMDはWi-Fiゲートウェイを検出するため、接続先アドレスを手入力して固定する必要はない。

PCページはローカル専用で、HMD通信はペアトークン、ブラウザー操作はCookie・CSRFで認証する。通信方式の根拠は[技術資料](../../research/implementation/offline-local-control.md)を参照する。

## 4. 必要な準備機能を選ぶ

PCとゴーグルに「トラッカー登録」「動作確認」「FB検査」「自由走行」を横並びで表示する。標準コントローラーのポインターとトリガーで選択でき、ゴーグル単体でも使える。A／Xでメニュー、B／Yで操作パネルを正面へ再配置する。パネルの再配置は計測原点を変えない。

| 機能 | 行うこと | 保存 |
|---|---|---|
| トラッカー登録 | 車体・左右車輪の識別と回転軸の校正。手首は任意で追加 | 登録一件分 |
| 動作確認 | 静止・前進・後退・左旋回・右旋回。一通り、または個別に選ぶ | 選んだ確認一件分 |
| FB検査 | 視覚または聴覚の固定した見本と、装着者の回答 | 検査一件分 |
| 自由走行 | 実際の左右車輪速度を音または棒で確認 | 保存しない |

登録後にほかの検査へ自動では進まない。動作確認・FB検査で登録や校正を消すこともない。ボタンを押せない場合は、付近に出る理由を確認する。「追跡中2／3台」なら接続と追跡を確認し、3台が有効になるのを待つ。

### トラッカー登録

1. 停止・着座して「トラッカー登録」を選び、静止の確認を待つ。
2. 案内に従って周囲を確認し、前へ約1 mゆっくり進んで止まる。
3. 後方を確認し、元の場所へゆっくり戻って止まる。
4. 車体・左右車輪の候補を実物に重なる目印と照合して確定する。
5. 必要なら左右の手首を順番に動かして識別する。手首を使わない機能確認では省略する。
6. 登録結果と保存・回収状態を確認し、準備画面へ戻る。

候補は自動確定しない。曖昧な場合は「実物を選ぶ」で左車輪・右車輪・車体の順に目印を指すか、PCから選び、前後進で校正する。機器A〜Eはこのアプリ内の目印で、HMDの番号1〜5やSDKの0〜4との対応を示さない。

前進で左右の回転軸を独立に求め、後退で整合性を確認する。キャンバーと任意の取付姿勢を扱い、車輪径や手とリムの位置合わせは不要。[識別・校正の条件](../specifications/measurement.md#機器識別と校正)

### 動作確認とFB検査

トラッカー登録の各動作前と、動作確認・自由走行の開始前は3秒の準備カウントダウンを使う。登録後に「動作確認」から一通り、または個別の動きを選ぶ。動作前には3秒の準備時間があり、コントローラーを置ける。対象の確認が終わると結果を表示する。

「FB検査」は停止中に視覚・聴覚を個別に選ぶ。視覚は先に表示位置を合わせる。音だけの検査はトラッカー未登録でも使える。固定した見本が実際の速度とは別であることを説明し、見えたか・聞き分けられたかを装着者が回答する。

### 自由走行

登録・校正後、静止して「自由走行」から視覚または聴覚を選ぶ。視覚では表示位置合わせも必要。3秒の準備時間の後、実際の左右車輪速度によるFBを開始する。時間制限や正式計時はない。モダリティを変えるときはいったん終了する。

走行中はパネルとポインターを隠す。PCの「自由走行を終了・FB停止」またはHMDのA／XでFBを止め、安全に静止すると操作パネルへ戻る。コントローラーを置いたことやPCとの切断だけでは終了しない。HMD中断・原点変更・校正無効化では中断し、復帰だけでは再開しない。

自由走行では位置姿勢・速度・視線・正式計時をファイルへ保存せず、来訪・試行も作成しない。PCに出る現在値はその場の確認用。測定精度の検証には[独立参照を用いる手順](../specifications/validation.md)を使う。

## 5. 参加者の装着後に確認する

HMDの「設定 → 入力 → アイトラッカー」で参加者ごとに眼球校正を行う。PCの「詳細設定・機器情報 → 表示位置と視線」で「眼球校正を確認済みにする」を押し、取得状態を確かめる。これは実施者の確認記録で、SDKによる精度の合格判定ではない。

着座・静止して正面を向き、PCの「表示位置を合わせる」またはHMDの「表示を合わせる」を押す。その後「FB検査」で視覚・聴覚の見本を個別に確かめる。車輪の識別動作は繰り返さない。PCの結果欄から特定の項目だけを再確認でき、別IDで保存する。対象外の項目を合格扱いにしない。

再装着・再接続・原点や固定の変更では[校正の有効性](../specifications/measurement.md#機器識別と校正)を確認する。実験中にHMDを外した場合は、再装着後に眼球校正・表示位置・追跡・固定・出力を再確認する。新しい来訪、HMD中断、原点変更では眼球校正の確認表示が解除される。

## 開始地点から離れるとVIVEの警告が出る場合

停止してHMDのソフトウェアバージョン、設定 → 一般 → トラッキングモード、設定 → 境界のプレイエリアを確認する。走行には「デフォルトモード＋ルームスケール」を第一候補とし、走路と停止場所を含む境界を設定する。半径1 mの固定エリアを作るインスタントモードは使わない。

通常の公称範囲は最大10×10 m。会場全体や、10 m直進に停止区間を足した範囲まで収まると決めつけず、実際の配置を確認する。自由走行で警告が出る場所と、その時点のPC上のHMD・走行用3台の追跡状態を照合する。

今回の警告を一般設定で完全に消す方法は未確認。Business+の管理機能も利用資格と対象設定の確認が必要。アプリはOSの警告を無効化せず、実際の追跡喪失に対する停止処理を維持する。[確認した公式資料と切り分け](../../research/implementation/vive-boundary-warnings.md)

## 困ったとき

| 状態 | 確認・対応 |
|---|---|
| 番号を承認できない | PCがHMDを検出したか、同じホットスポットか、AP有効化後にコンソールを起動したかを確認する |
| HMDアプリを完全再起動した | PCコンソールもCtrl+Cで終了・再起動し、ページを開き直して新しい番号を承認する。過去の試行は自動再開しない |
| 候補が複数・動作不足・追跡不良 | 停止して理由を読み、やり直すか実物選択・PC調整を使う |
| 視線が取得できない | HMDの標準設定と校正を確認する。欠測だけで速度FBや計時を止めず、取得不可として記録する |
| 保存・回収に失敗した | [記録の回収と復旧](records.md)に従う。未完了・未回収を確認する |

チェックの「確認済み」は機能についての結果。[独立参照による測定検証](../specifications/validation.md)と本計測開始の判断は別に行う。
