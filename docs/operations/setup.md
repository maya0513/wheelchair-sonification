# 導入・装着・準備

実施者がアプリを入れて機器の動作を確認するまでの手順。案内付きチェックはゴーグル単体でも行える。本実験は[PC操作](console.md)と[実験手順](../experiment-protocol.md)に沿って行い、参加者にメニュー操作を求めない。

## 用意するもの

| 機器・配布物 | 用途 |
|---|---|
| VIVE Focus Vision、VIVE Wireless Dongle | Android単体で計測・提示・保存 |
| Ultimate Tracker | 左車輪・右車輪・車体の3台が走行用。左右手首の2台は元データの追加記録用 |
| ノートPC、対応する`operator-console.zip` | オフライン接続、実験操作、正式計時、回収 |
| 対応する`WheelchairSonification.apk` | ゴーグルに入れるアプリ |

走行用3台でも機能チェックできる。研究計画の5台構成や本計測の受入れ条件を変更するものではない。実機で確認できた範囲は[確認状況](../status.md)に残す。

## 1. アプリとPCを用意する

1. [Releases](https://github.com/maya0513/wheelchair-sonification/releases)または配布一式からAPKとコンソールを入手する。Source codeのZIPは不要。
2. Focus VisionをWindows PCへUSB接続し、ゴーグルでファイル転送を許可する。APKを「内部共有ストレージ → Download」へコピーする。
3. ゴーグルのファイルブラウザーでAPKを開き、不明のアプリの許可を確認してインストールする。[HTC公式手順](https://www.vive.com/jp/support/focusvision/category_howto/installing-apk-on-headset.html)
4. 実施者用Ubuntu PCにNode.js 24以降を事前に用意し、対応コンソールを展開する。

APKとコンソールは同じ配布物を使う。通信形式は3。同じアプリID・署名鍵で更新し、署名不一致ならアプリのバージョンと鍵を確認する。アンインストールすると元データを失うため、更新の代わりに行わない。自分でAPKを作る場合は[ビルド手順](../development/android-build.md)を参照する。

| その他の同梱物 | 読み方 |
|---|---|
| app-overview.zip | 展開してMarkdownと画像付きの説明を読む |
| ui-preview.zip | 展開して`index.html`を開く。Unity・PC画像とWAV見本を閲覧する |
| build-info.json | ソース・ビルド設定・検査結果を確認する |
| SHA256SUMS.txt | ダウンロードしたファイルの一致を照合する |

これらの資料をHMDへコピーする必要はない。プレビューは実機の光学系・計測性能を再現するものではない。[画像・音の確認範囲](../development/xr-preview.md)

## 2. トラッカーを接続・固定する

HMDへドングルを取り付け、「設定 → 入力 → モーショントラッカー」でペアリングと環境スキャンを済ませる。アプリはHMDが取得した位置姿勢を使い、ペアリング自体は行わない。[HTCの設定手順](https://www.vive.com/jp/support/ultimate-tracker/category_howto/setting-up-vive-ultimate-tracker.html)

車輪用は回転する部分、車体用は剛性のあるフレームへ固定する。カメラを覆わず、手・衣服・車体・床との干渉、脱落、固定部のずれを確認する。背もたれの布だけを車体基準にしない。装着の強度・全走路の追跡は実機で確認する。

## 3. PCとゴーグルをつなぐ

1. PCのWi-Fi設定でホットスポットを作り、Focus Visionを接続する。会場のWi-Fiや外部回線は不要。
2. 展開したコンソールで`sh start.sh`を実行し、`http://127.0.0.1:8765/`を開く。リポジトリからは初回に`just setup`で準備し、`just start`で起動する。
3. ゴーグルでアプリを起動する。PCがゴーグルを検出したら、表示された6桁番号を照合し「接続を承認」を押す。

Unity・VIVE Hub・外部回線の常時実行は不要。コンソールはネットワークを切り替えず、起動時のホットスポットだけで機器通信を受ける。ホットスポットを後から有効にした場合はコンソールを起動し直す。HMDはWi-Fiゲートウェイを検出するため、接続先アドレスを手入力して固定する必要はない。

PCページはローカル専用で、HMD通信はペアトークン、ブラウザー操作はCookie・CSRFで認証する。通信方式の根拠は[技術資料](../../research/implementation/offline-local-control.md)を参照する。

## 4. 案内に沿って割当・動作を確認する

停止・着座して「チェックを始める」を選ぶ。標準コントローラーのポインターとトリガーで選択する。A／Xでメニュー、B／Yで操作パネルを正面へ再配置する。パネルの再配置は計測原点を変えない。動作前の5秒でコントローラーを置ける。

1. 車いすを止める。静止が続くと次の説明へ進む。
2. 周囲を確認し、前へ約1 mゆっくり進んで止まる。
3. 後方を確認し、後ろへ戻って止まる。
4. 車体・左右車輪の候補を、実物に重なる目印と照合して確定する。
5. 必要なら左右の手首を順番に上げ下げして識別する。手首を装着していない機能確認では省略する。
6. 停止・前後進・左右への旋回で、方向と左右差の取得を確かめる。
7. 停止したまま、視覚と聴覚の見本を順番に確認して回答する。
8. 結果と保存・回収状態を確認し、実験待機へ移る。

候補は自動確定しない。曖昧な場合は「実物を選ぶ」で左車輪・右車輪・車体の順に目印を指すか、PCから選び、前後進で校正する。機器A〜Eはこのアプリ内の目印で、HMDの番号1〜5やSDKの0〜4との対応を示さない。

前進で左右の回転軸を独立に求め、後退で整合性を確認する。キャンバーと任意の取付姿勢を扱い、車輪径や手とリムの位置合わせは不要。[識別・校正の条件](../specifications/measurement.md#機器識別と校正)

## 5. 参加者の装着後に確認する

HMDの「設定 → 入力 → アイトラッカー」で参加者ごとに眼球校正を行う。PCの「詳細設定・機器情報 → 表示位置と視線」で「眼球校正を確認済みにする」を押し、取得状態を確かめる。これは実施者の確認記録で、SDKによる精度の合格判定ではない。

着座・静止して正面を向き、PCの「表示位置を合わせる」またはHMDの「表示を合わせる」を押す。その後「装着後の短い確認」で表示と音の見本を確かめる。車輪の識別動作は繰り返さない。PCの結果欄から特定の項目だけを再確認でき、別IDで保存する。対象外の項目を合格扱いにしない。

再装着・再接続・原点や固定の変更では[校正の有効性](../specifications/measurement.md#機器識別と校正)を確認する。20分休憩後は眼球校正・表示位置・追跡・固定・出力を再確認する。新しい来訪、HMD中断、原点変更では眼球校正の確認表示が解除される。

## 困ったとき

| 状態 | 確認・対応 |
|---|---|
| 番号を承認できない | PCがHMDを検出したか、同じホットスポットか、AP有効化後にコンソールを起動したかを確認する |
| HMDアプリを完全再起動した | PCコンソールもCtrl+Cで終了・再起動し、ページを開き直して新しい番号を承認する。過去の試行は自動再開しない |
| 候補が複数・動作不足・追跡不良 | 停止して理由を読み、やり直すか実物選択・PC調整を使う |
| 視線が取得できない | HMDの標準設定と校正を確認する。欠測だけで速度FBや計時を止めず、取得不可として記録する |
| 保存・回収に失敗した | [記録の回収と復旧](records.md)に従う。未完了・未回収を確認する |

チェックの「確認済み」は機能についての結果。[独立参照による測定検証](../specifications/validation.md)と本計測開始の判断は別に行う。
