# Focus Vision単体でのトラッカー取得と校正

VIVE Focus Vision、VIVE Ultimate Tracker 5台、既存のVIVE Wireless Dongleを使用する。型番・台数・接続具の保有はユーザー確認による。5台の実動作と、このAPKによる実機取得・推定精度は別途確認が必要。現場の操作・取得・保存はゴーグル内で行い、PCへの常時接続や遠隔操作は必要としない。

使用車体は、ユーザー提示写真にあるキャンバー付きのスポーツ用車いす。傾斜角・寸法・製品型番を写真から決めない。一般的な車いすの垂直・平行な車輪を仮定せず、左右の軸を独立に3次元で求める。車体寸法、キャンバー、座面・クッション・固定具を実施記録へ残す。この車体で得た成績を一般用車いすや日常生活での技能へ直接一般化しない。

## 現地へ持ち出す前

1. [APKの導入](android-build.md)を行い、「かんたん確認」で日本語・3状態・音量・再配置を確認する。
2. ドングルは[メーカーの接続方法](https://www.vive.com/jp/support/ultimate-tracker/category_howto/attaching-dongle-to-focus-vision-or-focus-3.html)に従い、付属の延長ケーブルで本体へ固定する。USBハブや直差しを前提にしない。
3. 本体側で5台を設定し、現地に対応する追跡環境を準備する。アプリからOSのペアリングやマップ作成を代行しない。
4. 「機器・校正」で1台ずつ動かし、左手首・右手首・左車輪・右車輪・車体の役割を確認する。選択ボタンを押すと検出機器を巡回する。選択中の機器の移動速度[cm/s]も表示する。同じ機器の重複、未割当、切断を開始条件で検査する。

位置姿勢はVIVE OpenXR 2.5.1のUltimate Trackerプロファイルを使用する。入力ActionはOpenXR初期化前に有効にする。SDKが返す番号やserial文字列を物理個体の永久的な識別子と決めつけず、実行中のdevice IDも照合し、接続し直したら役割と校正を確認し直す。

## 校正画面の順序

| 段階 | 操作と確認 |
|---|---|
| 車体 | 水平な床で車体を静止し、初期の剛体姿勢を記録する |
| 左車輪・右車輪 | 車体を動かさず、それぞれ前進方向へゆっくり60°以上回す。収録開始と確定を押す。車輪の固定変換・回転軸・符号を求める |
| 左手・右手 | 手をハンドリムの異なる3位置に添え、それぞれ記録する。手首トラッカーの接触時の半径・軸方向位置を校正する |
| コース | 10 m直進の開始線・終了線へ同じ姿勢で車体を置き、位置を記録する。進行方向と中央2–8 mを定義する |

車輪を回す校正は参加者を乗せる前に行う。車体を安定して支持し、対象輪を床から離して回せることを補助者と確認する。車体を動かさず回せる支持方法がなければこの校正を進めず、現地での支持・固定手順を先に確立する。車輪を車体から外して別の場所で回す方法では取付位置を校正できない。

車輪校正では姿勢の変化から軸、回転軌道から中心を推定する。キャンバーは軸ベクトルに含める。トラッカーを車軸近くへ取り付け、位置の円運動が小さい場合は平均位置を中心候補とする。実装上は収録中の位置の広がりが1 cm以下の場合であり、中心へ正しく取り付けたことを独立に確認する。取付面からリムまでの軸方向差は手の校正で扱う。回転軸が大きく上下を向く、軌道が不安定、車体が動く、追跡が欠ける場合は校正を成立させない。

固定具が緩んだ、装着し直した、会場・計測座標が変わった場合は校正をやり直す。B/Yの「操作パネルを正面へ戻す」は計測座標のリセットとは別の操作である。

## 推定方法と初期の設定

`IPoseSource`を実機・合成データ・記録再生へ差し替え、共通の`PushEstimator`を通す。車体に対する車輪回転を連続角へ変換し、手とリムの近接、接線方向速度の整合、入り退出を分けた閾値から接触候補を推定する。接触候補の区間の回転角を主要側のFBへ渡す。力、接触圧、推進トルク、機械的効率は測っていない。

| 設定 | 初期値・扱い |
|---|---|
| 接触候補へ入る距離／離れる距離 | 0.04 / 0.07 m |
| 手と輪の接線速度の不一致 | 0.40 m/sまで |
| 入りの確認時間 | 0.02 s |
| 許容する時刻間隔 | 最大0.10 s。欠測をまたぐプッシュは無効 |
| 停止速度 | 0.04 m/s未満 |
| 旋回判定 | 車体の向きの変化12°/s超、またはコースとの向きの差10°超 |
| 制動候補 | 速度低下0.4 m/s²超 |
| 異常な輪回転 | 720°/s×間隔＋5°を超える跳びを無効化 |
| 車輪校正の円軌道残差 | 平均1 cm以下。研究用の角度精度とは別の内部確認 |
| コースの取得距離 | 9.5–10.5 m。実際の取得距離も保持し、10 mへ強制的に尺度を合わせない |

これらは**未検証の初期工学値**で、原著から得た最適値ではない。予備記録で調整し、別の未使用記録で[受入れ基準](../specifications/validation.md)を満たすか確かめる。閾値と校正値は各記録に残す。正常値による欠測の埋合せ、最後の角度の再利用、接続不良時の模擬入力への自動切替は行わない。

## 停止中の設定と実測開始

「実験設定」で研究用ID・主要側を選ぶ。事前直進2反復の有効角から目標を求め、割付群を設定すると固定する。基準が成立しない場合は訓練へ進めない。正常に完了した同じ基準反復を上書きする操作は設けない。[基準量と再試行の研究上の規則](../experiment-protocol.md#試行成立と再試行の規則)を優先する。

課題・時点・反復を選び、「実測開始」を押すと10秒の準備時間に入る。停止・追跡の成立を確認して計測へ進み、操作画面を隠す。コントローラーを手放したことだけで実測を止めない。5台すべての追跡有効性を確認し、推進角は主要側の手首・車輪と車体を使い、中央区間・直進・訓練でだけFBを返す。

A/Xは停止要求に使う。動いている間は提示を止め、停止後に操作画面を戻す。追跡が失われて停止を判定できない場合は、物理的に停止した上で確認ボタンを使う。この確認で追跡や校正を有効に戻すわけではない。アプリ中断やHMD追跡喪失では、その試行を未完了として保持し、自動再開しない。

90分の手順、訓練の3セット、切替・休憩、20分の保持休憩は[実験手順](../experiment-protocol.md)に沿って実施者が管理する。アプリは試行単位の記録であり、20分休憩を自動保証するタイマーではない。

直進のコース走行後の停止、訓練120秒、8の字の評価上限60秒などを試行管理に使う。**アプリの終了判定や経過時間は主要評価の採点ではない。** 完了、経路、接触、開始・終了フレームは外部動画で採点する。

## 屋外での確認

屋外を第一候補とするが、低照度・直射日光での使用はメーカー非推奨。実施予定の床・照明・時間帯で、全方向、車輪の連続回転、手・スポーク・身体による遮蔽、パススルー視認性、装着の干渉を確認する。成立しない場合は会場または構成を見直す。研究参加者で試行錯誤して必要量を補わない。
