# PC操作とオフライン接続

ゴーグル単体の準備は[装着・チェック](tracker-measurement.md)を参照。本実験の進行は実施者が[手順表](../experiment-protocol.md)に沿って判断する。自動で課題を進めるアプリではない。

## 起動と接続

```sh
just experiment-console-demo  # 実機なしの画面デモ。確認番号123456
just experiment-console       # 実機用
```

配布ZIPはNode.js 24を用意して `sh start.sh` で起動する。ブラウザーは `http://127.0.0.1:8765/`。Unity・VIVE Hub・外部回線の常時実行は不要。

先にPCのWi-Fi設定でホットスポットを作り、Focus Visionを接続する。コンソールはネットワークを勝手に切り替えない。起動時のAPインターフェースだけへ機器通信を公開し、HMDはWi-Fiゲートウェイを検出する。APを後から有効にした場合はサーバーを起動し直す。

PCがゴーグルを検出すると番号入力を承認できる。HMDの6桁番号を照合し「接続を承認」を押す。未検出の間は接続待ちの理由を表示する。PCページはローカル専用、通信はペアトークン、ブラウザーはCookie・CSRFで認証する。

**通信形式3の同じ配布物を組み合わせる。** HMDアプリを完全再起動した場合は、PCコンソールもCtrl+Cで終了・再起動し、ページを開き直して新しい番号を承認する。元データは消えず、過去の試行は自動再開しない。

## 四つの画面

| 画面 | 操作 |
|---|---|
| 準備・チェック | HMDと同じ案内・割当候補・進捗・結果。車いす図と役割別の状態。詳細欄で入力・音量・機器・手動校正を調整 |
| 実験 | 参加者・群、時点・課題・反復を手動登録。記録と正式計時を操作 |
| 回答 | 音・表示の見本、口頭回答、理解確認・質問紙をPCへ保存 |
| 記録 | 実際の保存先、コピー・照合結果、再回収、USB用の書き出し |

準備の状態・判定はHMDが管理する。PCは同じ操作を要求し、反映された状態を表示する。古い画面・同時操作・記録中の設定変更は理由付きで拒否する。

画面デモはUnityの共通処理から生成した合成状態を使うUI確認用で、自動識別や実機の検証ではない。合成入力を実測の接続不良時に自動で使うことはない。

「装着後の短い確認」は表示・音の見本だけを確認する。結果欄から項目別の再確認もできる。判定設定は詳細欄に置き、変更したら割当・校正を取り直す。

## 本実験

1. 参加者ID・群を登録し、時点・課題・反復を選んで「課題を登録」する。
2. 「記録開始」。HMDの応答後、評価では「3秒準備 → 開始合図」を押す。
3. ゴールを見て「計時終了」またはSpaceを押す。入力欄・選択欄の編集中はSpaceを使わない。
4. 訓練では目安2分で「訓練終了・FB停止」。安全に止まるまで元データを残す。
5. 安全停止後に「記録終了」。PCへのコピー・チェックサム照合を確認する。

主ボタンは現在の状態に合わせて表示する。未登録の参加者・群・課題の変更があれば開始を案内し直す。ブラウザーを再読込した場合、既に動いている試行の時計を復元したように扱わず、中止して新しい記録でやり直す。中止と正常な記録終了は別操作。正式な時計はPCの単調時計で、HMDへの通信時間から計算しない。実際の音の出力時刻は別途確認する。

2分・20分タイマーは通知だけで、自動終了・移行・操作制限はしない。休憩中にHMDを外してもPC時計は動く。本実験中の通信断、HMD中断、保存失敗では提示・試行を未完了停止し、復帰だけでは再開しない。身体の安全停止は実施者が行う。

## 保存

PCの初期保存先は `~/WheelchairSonificationData/`。元データはHMDに残し、終了した試行と単体チェックをZIPで回収する。失敗は「未回収の記録をコピー」で再試行する。[保存項目・USB回収](research-records.md)

コピーの失敗や未完了記録を無視して本計測へ進めない。実施の可否は[開始条件](../operations/study-operations.md#本計測開始条件)で判断する。
