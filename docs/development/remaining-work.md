# 残作業と確認証拠

PC上の実装・検証と、実機・予備実験・責任者の確認を分けて管理する。研究条件の定義は[実験手順](../experiment-protocol.md)、技術性能の合格条件は[検証計画](../specifications/validation.md)、本計測の可否は[実施運営のG1–G6](../operations/study-operations.md#本計測開始条件)に従う。

## ソフトウェアの作業

| ID | 作業 | 状態・証拠 |
|---|---|---|
| S1 | PCのオフライン操作、接続承認、被験者用画面との分離 | 実装済み。ローカルHTTP・認証・期限切れ要求のテスト、Unityの画面・接続テスト |
| S2 | 来訪全体の課題順、反復、理解確認、割付ゲート、休憩 | 実装済み。固定時計の単体テストとUnity結合テスト |
| S3 | 校正の共通部分と個人部分、明示的な入力方式 | 実装済み。左右の傾斜軸、欠測、役割・再接続の合成入力テスト |
| S4 | 中止・再試行・再起動・未測定基準の復元 | 実装済み。二重命令、古い状態、切断、保存失敗、復元のテスト |
| S5 | 来訪・試行の保存、ZIP回収と照合、USB用出力 | 合成入力の20試行をPCへ回収し、ZIP外側と内部143ファイルのSHA-256が一致。MediaStoreと実機コピーは下表の確認が必要 |
| S6 | 実画面PNG、切り出し、画像一覧の目視 | Unityの被験者画面22件、Chromeの実施者画面18件を生成。文字・ゲージ・役割設定・小さいPC画面を目視確認。配布時に同じコミットから再生成 |
| S7 | 実時間90分のUnity＋PC継続試験 | 模擬来訪と回収は完了。全20試行の再解析が一致。継続稼働は約84.5分で利用者の指示により中断。90分の成功証拠はなく、先行公開の明示指定で配布する |
| S8 | 署名付きAPK、静的検証、commit・push・Release | 署名付きAPKと静的検証が成功。公開v0.2.0と署名が一致し、versionCode 2→3を確認。配布コンソールの単独起動を確認。Releaseは未公開 |

補助スクリプトの結果は`.local/logs/`とテスト出力、Unityの結果は`unity-test-edit.xml`・`unity-test-play.xml`に残す。画像は`.local/ui-preview/`・`.local/console-preview/`、実時間試験は`.local/console-integration-*/result.json`に残す。早期確認を途中で止めた記録を、90分の成功として扱わない。

通常の公開処理は、現在のCore・Runtime・PC通信サーバーと同じソースの実時間試験について、90分、来訪完了、ZIP回収を検査する。先行公開の明示指定では90分の検査だけを省略し、Releaseとビルド情報へ未完了と記録する。[公開手順](android-build.md#ビルド・公開する)。テスト用の偽の結果は単体テスト内だけに作り、実際の公開には使わない。

## PC上の確認証拠

| 対象 | 確認結果 |
|---|---|
| 自動テスト | Unity Edit Mode 76件・Play Mode 25件、補助スクリプト56件が成功 |
| 保存データの再解析 | 合成入力で記録した全20試行について、角度・状態・無効理由が一致。元ファイルを変更せず再解析 |
| 訓練区間 | 6回とも約120秒で終了し、区間終了後の追加FB開始は0件。正常入力の時刻拒否も0件 |
| 連続稼働 | Linux Unity＋PCサーバーで5071秒まで稼働。利用者の指示により中断したため90分試験は未完了。模擬来訪・回収後の待機時間を含む |
| 回収 | PCへ転送したZIPのSHA-256と、内部143ファイルのSHA-256が一致 |
| 画像 | APKと共通のUnity UI 22件、Chromeの実施者画面18件を生成・目視。長い質問項目の見切れを修正して再生成 |
| APK | ARM64・非デバッグ・OpenXR・対象SDK 36・通信権限・ライセンス・署名を検証。公開済みAPKとの証明書一致を確認 |
| 配布コンソール | ZIPをリポジトリ外へ展開し、Node.jsのみでサーバー・HTML・JS・CSSを起動。Unity・Gitリポジトリへ依存しないことを確認 |

再解析の集計は`.local/replay-verification-ca282bb.json`、配布物の照合は`.local/distribution-check-ca282bb/`、中断記録は`.local/console-integration-2026-10-21T05-43-57-898Z/failure.json`に残す。テスト用の参加者・位置姿勢は合成入力で、実験参加者の記録ではない。公開するAPK・コンソール・画像は、公開処理で同じコミットから生成する。

実時間試験は、模擬来訪終了後も同じプロセスと通信を維持する時間を含む。説明・装着・校正の実作業や、実際の参加者が90分以内に終わることは、下表の予備実験で確認する。

## 実機・現地で残る作業

| 担当 | 操作・確認 | 残す証拠・判断 |
|---|---|---|
| 学生研究者 | 同じ署名でのAPK更新、起動・復帰・再起動 | 本体OS・ファームウェア、アプリ版、実施日、成功／失敗。端末内記録を保全 |
| 学生研究者 | このPCのホットスポットへFocus Visionを接続し、全走路で操作・切断・復旧 | 接続を維持した範囲、帯域、状態の鮮度、切断から提示停止までの時間。AP対応フラグだけで合格にしない |
| 学生研究者・安全補助者 | 5台同時取得、装着・役割、左右車輪の回転、遮蔽、再接続 | 機器・固定具・椅子の寸法と設定、追跡記録。日光・照度・床面・走路の条件 |
| 学生研究者・安全補助者 | 着座・走行中の実空間、文字・ゲージ、3音と安全指示の知覚 | 画面画像との差、不快感、停止判断。コントローラー操作を被験者へ求めない |
| 学生研究者・採点担当 | 調整に使っていない記録による接触・角度・状態・実出力の検証 | [受入れ基準](../specifications/validation.md)の全項目。API時刻を実出力時刻とみなさない |
| 学生研究者 | 実機で90分以上の追跡・通信・電池・処理・保存、ZIP転送とUSB回収 | ゴーグルの実記録、エラー、空き容量、コピー後のチェックサム |
| 学生研究者・予備参加者 | 必要な同意・手続きを経た2–3名の通し予備実験 | 設営・校正・理解・移動・質問紙を含む実時間、負担、逸脱。合成入力の90分とは別 |

合成入力は動作推定の正解データや測定精度の証拠ではない。屋外が第一候補だが、直射日光・低照度等で成立しない場合は会場を見直す。90分に収まらなくても休憩や評価条件を短縮して救済せず、条件確定前に手順を再検討する。

## 教員・運営側で残る作業

| 担当 | 決める・確認すること | 完了の証拠 |

| 教員・研究責任者 | 倫理手続きの適用・承認、募集・同意・撤回・撮影・事故対応 | 承認情報または学内判断、連絡先入りの最終書類 |
| 学生研究者・責任者 | 会場の使用、2名体制、安全補助者と採点担当 | 日程、実名の担当、現地寸法・点検・訓練 |
| 責任者 | 正式保管先、アクセス権、保存期間、バックアップ・削除・撤回期限 | 学内規則と最終同意書、実際のアクセス・復元確認 |
| 学生研究者・責任者 | 予備実験後の設定・書類・分析・割付条件の固定 | [条件確定記録](../operations/record-forms.md#条件確定の記録)、設定と使用コミット |

G1–G6は実際の証拠が揃うまで未完了である。ソフトウェアのテスト成功、APKの署名検証、プレリリース公開を本計測の開始許可へ読み替えない。
