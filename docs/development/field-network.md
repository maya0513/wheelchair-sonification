# 会場のWi-FiなしでPCとゴーグルをつなぐ

このUbuntu PCを会場へ持ち込み、PCのホットスポットにFocus Visionを接続する。実施者はこのPCのブラウザーから操作し、被験者に設定をさせない。[採用する操作設計](../specifications/operation-flow.md)

## 確認済みと未確認

2026-10-20、このPCのNetworkManagerが無線LANの`WIFI-PROPERTIES.AP: yes`を返し、ドライバーの対応モードにも`AP`があることを確認した。これはアクセスポイントを作る能力の確認であり、ホットスポットはまだ有効化していない。現在のWi-Fi接続設定も変更していない。

**会場のWi-Fi・インターネット回線・SIMは不要。** PCとゴーグルの間のローカル通信だけを使う。APKのダウンロード、初回の機器設定・更新など、事前にインターネットが必要な準備は持出し前に済ませる。

以下は未確認である。

- Focus VisionがこのPCのホットスポットへ接続し、インターネットなしの接続を維持すること。
- 直進・8の字・停止域全体で、実施者のブラウザーとの通信が安定すること。
- 5台のUltimate Trackerと併用したときの通信・追跡・電池・処理負荷。
- 実機とPCの遠隔操作・切断時動作。ブラウザー操作は実装済みで、ソフトの試験とは別にFocus Visionで確認する。

## 接続の形

```text
このUbuntu PC：一時的なWi-Fiを作る ＋ ブラウザーで操作
                 ⇅ ローカル通信（インターネットなし）
Focus Vision：そのWi-Fiへ接続、計測・FB・保存は本体で実行
                 ⇅ 既存ドングル
            Ultimate Tracker 5台
```

ゴーグルから画面をPCへ動画配信することを通常操作の前提にしない。課題・状態・警告・操作に必要な小さいデータを送る。センサーからFBまでの経路をPCへの通信へ依存させない。

## 実施者が事前に行うこと

1. UbuntuのWi-Fi設定からホットスポットを作る。名前と十分な強度のパスワードを決め、オープンなネットワークにしない。[Ubuntu公式手順](https://help.ubuntu.com/stable/ubuntu-help/net-wireless-adhoc.html.en)
2. Focus Visionを接続する。ネットにつながらない旨の表示は、PCとゴーグルの通信可否とは区別する。OSが他のネットワークへ切り替えないことも確認する。
3. `just experiment-console`を起動し、`http://127.0.0.1:8765/`を開く。ゴーグルの確認番号で装着前に接続承認する。[具体的な操作](experiment-console.md)
4. ゴーグルを被験者へ渡す前に、機器・保存先・操作端末を確認する。PCの自動スリープを止め、90分以上の電源を確保し、走路外へ置く。
5. 通信切断時の停止・未完了保存・復旧を予備確認する。操作できる範囲を会場で実測する。

このPCは現在Wi-Fiで接続している。ホットスポットへの切替では現在の接続が切れる可能性があるため、作業中に自動で切り替えない。実験中に外部インターネットを同時に使う構成は不要。

5 GHzを候補とするが、このPCの5 GHzでのAP動作は未検証。実際の機器・地域設定で使える帯域を確認し、5台の追跡と同時に安定性を測る。新しいルーターやアダプターの購入は前提にしない。

## 保存とアクセス

元データはゴーグルへ保存する。PCのブラウザーを閉じても保存済みの試行を失わない。遠隔操作は接続した実施者だけに許可し、実名・同意書を配信しない。実験用ネットワークをインターネットへ公開しない。

通常はPCからZIPを回収・照合し、[Download経路](research-records.md#windowsへ取り出す)も維持する。このPCで回収する場合も、アクセス制限のある研究用保管先へコピーしチェックサムを照合する。学内の正式な保管先・保存期間は責任者確認待ち。

通信と権限の技術的根拠は[調査メモ](../../research/topics/offline-local-control.md)にまとめる。

## 通信の構成

操作画面はPCのループバックだけへ配信する。ゴーグル用HTTPはNetworkManagerで有効なAP接続のIPv4アドレスだけで待ち受ける。通常のインターネット用Wi-Fiへ勝手に公開せず、ホットスポットがなければ設定方法を表示してPC内の画面だけ起動する。

ゴーグルはWi-Fiの経路情報からゲートウェイを求め、固定ポート8765へ接続する。インターネットへの到達判定を接続の必須条件にしない。ネットワーク・サーバーが変わったら再承認し、既存の試行は自動再開しない。実施者画面はこのPC専用で、同じLANの別端末に操作画面を配信する構成ではない。

端末の権限、APの帯域、ファイアウォール、走路の電波状況は実接続で確認する。アプリのManifestにはInternet・ネットワーク状態を宣言し、target SDK 36とローカルHTTP設定を検査する。ネットワーク設定やファイアウォールをコマンドから自動変更しない。PC通し試験はループバックであり、Wi-Fi到達範囲の証拠ではない。
